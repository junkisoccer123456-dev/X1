# 使用した構文：リアル事例スペック公開型（参考投稿④）

①善意の共有として切り出す → ②スペックを箇条書き → ③結果を箇条書き → ④会ったときの肌感 → ⑤なぜその結果かの解説 → ⑥表面的な要因を否定 → ⑦再現可能な戦い方に一般化

## ⚠️ この10本の使い方（重要）

この構文は**実在の事例が前提**です。スペックや結果の数字を創作すると嘘になるため、
`【　】` を**実際に面接した方の数字に置き換えてから投稿**してください。
解説パートは田村さんの視点で書いてありますが、事例に合わせて調整してください。
個人が特定されないよう、社名・案件名は書かないでください。

最終的に選んだ理由がこちら。
・【理由1：例）配属チームの人と事前に話せた】

この方、いちばん高い提示を選んでません。

金額は入社時点の評価で、環境は3年分の成長に効きます。どちらを取るかは自由ですが、比較する材料を並べてから決めた人は、あとで揺れないんですよね。

コードを書く量は減ります。その代わり、事業側と直接話せる立場になる。ここを理解して受けた人は、入ってからのギャップが小さいかと。
