# 構文名：リアル事例スペック公開型

## この構文が読まれやすい理由
- 「指標になりそうだったので共有しますね」という入り方が**善意の共有**に見え、宣伝感がゼロ。
- スペックを箇条書きで出すと、読者は勝手に自分と比較する。年齢・年収・経験年数は**自分ごと化装置**として最強。
- 結果（内定数・期間）を先に出してから理由を解説するので、「なぜ？」で引っぱれる。
- 解説が「僕が面接で本当に見ているのは〜」と、**その立場の人しか言えない情報**になっている。
- 最後に再現可能な戦い方へ一般化するので、他人の事例なのに自分の行動指針として保存される。

## 基本構造
```
①「先日、〇〇だった方の状況が指標になりそうなので共有します」
 ↓
②スペックを箇条書き（年齢／経験／技術／年収／希望／応募先）
 ↓
③結果を箇条書き（内定数／期間）
 ↓
④会ったときの肌感を一言で（「〇〇な人でした」）
 ↓
⑤なぜその結果になったかを、発信者の視点で解説
 ↓
⑥「〜だけでは決まっていません」と、表面的な要因を否定
 ↓
⑦再現可能な戦い方に一般化して締める
```

## 抽象テンプレート
```
先日、【場面】の方の【状況】がこんな感じで、
【読者】の指標になりそうだったので、ぼくの肌感を添えて共有しますね。

・年齢：【　】
・経験：【　】
・技術スタック：【　】
・直近年収：【　】
・希望年収：【　】
・応募先：【　】

結果がこちら。
・【結果指標1】：【　】
・【結果指標2】：【　】

会ったときの肌感を正直に言うと、「【人物評】」でした。
僕が【立場】で本当に見ているのは、【表面的な指標】より「【本質的な指標】」なんですよね。
【具体的にその人ができていたこと】。

【結果】が出たのも、たぶん「【表面的な要因】」だけでは決まっていません。
【本質的な要因】だから、【有利な状況】を自分で作れたかと。

【再現可能な戦い方】。これが【領域】でいちばん強い戦い方かと。
```

## 相性の良いテーマ
- 実際に会った人・見た書類の事例が手元にあるテーマ
- 読者が「自分はどの位置か」を知りたいテーマ（年収、年数、通過率）
- 結果の数字（内定数・期間）が出せるテーマ

## 相性の悪いテーマ
- 事例が手元にないテーマ（**創作すると嘘になる**ので使わない）

## ⚠️ 運用上の最重要ルール
この構文は**実在の事例が前提**。スペックや結果の数字を創作してはいけない。
生成時は必ず【　】のプレースホルダで出力し、
**実際に面接した方の数字を本人が埋めてから投稿する**こと。
個人が特定されないよう、社名や固有の案件名は書かない。

## 文体・見た目のメモ
- 文章量：400〜600字
- スペックは「・項目：内容」で統一
- 解説パートは「〜なんですよね」「〜かと」で語る
- 絵文字なし

## バリエーション

### A. 年収予想投げかけ型（2026-10-05 追加・参考投稿③）
結果・解説を**全部出さずに**、スペックだけ出して読者に予想させる派生。
リプ欄の予想がそのままエンゲージメントになるので、拡散を狙うときに使う。

```
①権威フック＋「この方がもし転職したら...」で引っぱる
 ↓
②スペックを箇条書き（年齢／現年収／実務経験／開発言語）
 ↓
③「その他：」で現場での役割を1〜2行だけ足す（＋で補足を継ぐ）
 ↓
④「年収いくら出ると思いますか？リプで予想してみてください↓」
 ↓
⑤ハッシュタグ1つ
```
ポイント：
- **答えを書かない**。解説を足すと予想する理由が消える
- スペックは4項目＋「その他」。多すぎると予想しづらくなる
- 「その他」に書くのは**年収を左右する実務の中身**（本番運用、障害対応、移行経験）。
  ここがあると予想に幅が出て、リプが伸びる
- 空行を多めに取って、スペックのかたまりを浮かせる
- ハッシュタグはこの型だけ使ってよい（予想を募るので、外からの流入を狙う）

### B. 経歴列挙＋常識反論型（2026-10-05 追加・参考投稿⑧）
結果（内定数・期間）を出さず、**経歴を10〜12項目の箇条書きで出して**、
最後に**世間の常識への反論**で締める派生。

```
①権威フック＋「先日面接に来られた方が〇〇で、△△を信じている方に見てほしい内容だったのでシェアします」
 ↓
②1行目だけスペック（・年齢／実務年数／現年収 を1行にまとめる）
 ↓
③2行目以降は経歴を時系列＋現在の業務内容で10〜12項目（1項目1行）
 ↓
④不利な事実も隠さず入れる（「転向時は年収が70万下がっている」）
 ↓
⑤「正直、〇〇で言えば△△のほうが上です。本人もそう言っていました。」＝弱点を先に認める
 ↓
⑥「それでもこの方を評価したのは、【本質的な理由】でした」＋具体例をカギ括弧で2つ
 ↓
⑦常識への反論（「〇〇説がよく話題になりますが、実際に選考している立場からいうと、
　 △△で落ちているというより、□□な方を落とします」）
 ↓
⑧逆説で一般化して締める（「逆に言えば、〜を1回でも持てるかどうかが鍵」）
```
効いているのは3点。
- **不利な事実を自分から入れる**（年収が下がった、コードは20代のほうが速い）。
  都合のいい事例に見えなくなる
- 常識（35歳限界説）を否定しきらず、**「年齢ではなく中身で落としている」と言い換える**。
  反発を買わずに主張が通る
- 締めが読者の行動（30代のうちに判断する側に回る）に落ちる
