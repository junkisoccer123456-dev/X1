# 構文名：3段階格付け→本命公開型

## この構文が読まれやすい理由
- 「ダメ／無難／本命」と**格付けする姿勢**そのものが強い。読者は自分の候補がどこに入るか確認したくなる。
- 最初にNG群を出すので、「自分が狙っていたところがダメ側だった」という驚きで止まる。
- 本命だけを伏せて切るため、リプが必ず開かれる。
- リプを1項目1リプに分けてカウントダウンすると、最後まで追われる。
- 締めが個別の推薦ではなく**方法論の結論**なので、読後に行動指針が残る。

## 基本構造
```
①いま動くべき理由（タイミング）＋「〇〇↓」
 ↓
②ダメな群（ラベル＋理由）＋3項目
 ↓
③無難な群（ラベル＋理由）＋3項目
 ↓
④「本当におすすめは…↓」で切る
 ↓
⑤【リプ】本命をカウントダウンで1つずつ公開
　　　　　各項目は「概要 → 根拠となる事実 → 特徴 → 一言評価」で統一
 ↓
⑥最後に全体の結論（方法論に一般化）
```

## 抽象テンプレート
```
【いま動くべき理由】、【行動】の一番いいタイミング↓

【ダメ群のラベル】（【理由】）
・【項目1】 ・【項目2】 ・【項目3】
【無難群のラベル】（【理由】）
・【項目4】 ・【項目5】 ・【項目6】
本当におすすめは…↓

【リプ】本当のおすすめ Best【n】
【n】【項目名】
【概要】。【出典のある事実・数値】。【特徴】。
【一言評価（ただし短所も添える）】

（…①まで1リプずつ）

【立場】として断言できるのは、【方法論の結論】ということ。
```

## 相性の良いテーマ
- 選択肢が多く、優劣や難易度に差があるテーマ
- 「みんなが狙うところ」と「実は狙い目」のギャップがあるテーマ

## 相性の悪いテーマ
- 優劣をつけると角が立つテーマ
- 根拠が出せないテーマ（格付けは根拠がないと悪口になる）

## バリエーション

### A. ランク分け型（条件で格付けする・参考投稿⑩）
格付けの対象を**企業名ではなく条件**にする派生。社名を出さずに成立するので、事実確認の負担が軽い。
`入っても伸びない／そこそこ伸びる／一気に伸びる` のように3層へ分け、最上位だけリプで公開する。
リプ1の最後に「共通点は…」ともう一度引っぱり、リプ2で回収する**二段引き**が効く。
参考：`../references/2026-09-23/11-伸びるSaaS見分け方.md`

### B. 2段階版（2026-09-23 追加・参考投稿⑤）
「やめとけ」を省き、**穴場（銀）と本命（金）の2段階だけ**にする派生。
否定する対象がないので、企業名を出しても角が立たない。実名リストを使いたいときはこちらが安全。
リプの解説は個別の推薦ではなく、**構造の説明**（「倍率は良し悪しではなく知名度と応募数で決まる」）にすると納得感が出る。
参考：`../references/2026-09-23-nori/05-BtoB2段階.md`

## ⚠️ 運用上の注意
- 実在の企業を「やめとけ」側に置くと、事実ではなく評価が断定として広まる。
  **企業名で格付けする場合は、必ず出典のある事実に限り、評価は「未経験の枠が少ない」など条件の話に留める。**
  迷う場合はバリエーションA（条件で格付け）を使う。
- 数値を入れる場合は有報・公式情報など出典のあるものだけ。生成時は `【　】` にする。
