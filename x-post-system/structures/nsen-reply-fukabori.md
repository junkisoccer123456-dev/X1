# 構文名：n選＋リプ個別深掘り型

## この構文が読まれやすい理由
- 本文だけで「5つの答え」が揃うので、**本文単体で保存される**。リストに1行解説が付いているぶん、
  ただの羅列より信頼感が出る。
- そのうえでリプに同じ5項目の長文解説を置くので、**気になった1項目だけ読みに行ける**。
  「全部読まなくていい」構造なので、リプの開封率が落ちにくい。
- 本文の締めで一度**価値を下げる**（「資格は実務経験の代わりにはならないです」）のが効いている。
  煽らずに「が、〜には効く」と限定するので、売り込みに見えない。
- リプの各項目が「概要 → 難易度・性質 → 採用側の本音 → 面接でどう効くか」で統一されていて、
  **選ぶ側しか書けない情報**になっている。だから他のまとめ記事と差がつく。

## 基本構造
```
①【〇〇n選】の見出し（カギ括弧ではなく【】で囲む）
 ↓
②誰向けかを1行（「〇〇な人が、次の△△を一段上げるならこれかと」）
 ↓
③❶項目名（補足）
　 1行の価値説明
　 ❷〜❺まで同じ形（解説は1〜2行まで）
 ↓
④価値を一度下げる（「〇〇は△△の代わりにはならないです」）
 ↓
⑤「が、〜としては〇〇を一段押し上げます↓↓」で切る
 ↓
⑥【リプ❶〜❺】同じ項目名で再登場
　　　　　　　 ・概要（何を問われるものか／どういう性質か）1〜2行
　　　　　　　 ・「採用側として正直に言うと」＋採用側の見え方
　　　　　　　 ・面接・書類でどう効くか（1文）
```

## 抽象テンプレート
```
【【対象読者】こそ〇〇して損しない【テーマ】n選】

【対象読者】として【経験の前提】人が、次の【上げたいもの】を一段上げるならこれかと。

❶【項目名】（【正式名称・補足】）
【1行の価値説明】。【どう強くなるか】。

❷【項目名】
【1行の価値説明】。【希少性の一言】。

❸【項目名】
【1行の価値説明】。

❹【項目名】
【1行の価値説明】。

❺【項目名】
【1行の価値説明】。

【テーマ】は【本質的なもの】の代わりにはならないです。
が「【限定された効き目】」としては、【読者の資産】を一段押し上げます↓↓

【リプ❶】
❶【項目名】（【正式名称】）
【何を問われるものか】。【難易度や性質の比較】。
【立場】として正直に言うと、これを持っている人は「【採用側の第一印象】」と最初に目が留まる。
【面接でどう効くか】。

（…❺まで1リプずつ）
```

## 相性の良いテーマ
- 選択肢が4〜6個に絞れて、**1つずつに語れる中身があるテーマ**（資格、職種、ポジション、技術領域、職務経歴書の武器）
- 読者が「どれを選べばいいか」で止まっているテーマ
- 発信者が「選ぶ側の見え方」を付け足せるテーマ

## 相性の悪いテーマ
- 項目が10個以上あるテーマ（リプが多すぎて読まれない。網羅リスト型のほうが向く）
- 1項目に書けることが1行しかないテーマ（本文とリプが同じ内容になり、二度書きが無駄になる）
- 優劣をつけたいテーマ（この型は並列。順位を付けたいならカウントダウン型）

## 文体・見た目のメモ
- 文章量：本文300〜450字／リプ各150〜250字（本文より少し長い程度に抑える）
- 項目番号は ❶❷❸❹❺（黒の囲み数字）。本文とリプで**同じ番号・同じ項目名**を使う
- 本文の解説は1〜2行で止める。ここを長くするとリプを読む理由が消える
- リプには必ず「採用側として」「正直に言うと」の一言を入れる。ここが差別化点
- 絵文字なし（囲み数字は記号として使う）
- CTAは入れない（本文の「↓↓」がリプへの誘導を兼ねる）

## ⚠️ 運用上の注意
各項目の難易度・試験内容・名称は事実なので、**正式名称と内容を間違えない**こと。
合格率などの数字は出典がないと書けないため、「上位資格」「実技試験」のような
**性質の説明に置き換える**。
