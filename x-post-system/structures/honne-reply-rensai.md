# 構文名：本音提起→リプ連載解説型

## この構文が読まれやすい理由
- 冒頭が「技術は優秀そうなのに」という**逆説**。優秀な自覚がある人ほど「自分のことでは」と引っかかる。
- 本編で扱うのは"考え方"だけ。具体例をリプに逃がすので、本編が短く読み切れる。
- 予防線（「※媚びろという話ではない」「合わない現場もある」）を先に置くことで、反発コメントを封じている。この一行があるかないかで炎上率が変わる。
- 「下にn個...」で本文が終わる。**数を予告して切る**ので、リプが必ず開かれる。
- 各リプが「見出し → 実際にあった場面 → 採用側の解釈 → どうすれば評価されるか」で統一されているため、読者は同じリズムで最後まで読める。
- 場面描写にセリフが入るので画が浮かび、抽象論に落ちない。

## 基本構造
```
①逆説の本音（「〇〇なのに、××で落ちる」）
 ↓
②世間の傾向を指摘（みんな△△ばかり見ている）
 ↓
③本当に見られているものを提示
 ↓
④予防線（※〇〇という話ではないです）
 ↓
⑤例外の許容（合わない現場もある）
 ↓
⑥今整えておく価値（将来が楽になる）
 ↓
⑦「下にn個...」で切る
 ↓
⑧【リプ①〜⑦】各項目を4段構成で解説
   見出し → 実際にあった場面（セリフ入り） → 採用側の解釈 → どうすれば評価されるか
```

## 抽象テンプレート
```
【領域】で、実は地味に多い【ネガティブな結果】が
「【一見よさそうな状態】なのに、【本当の理由】」と思われるパターン。

今は【世間が熱心な対象】に力を入れる人が多いです。
ただその一方で、"【抜けている観点】"がスッポリ抜けてる人が一定数いるな、と感じます。

【相手】が期待してるのは、【表面的な能力】以上に「【本当に欲しい安心感】」だったりします。
※【誤解されそうな解釈】という話ではないです。

もちろん【例外】もあるので、そこは【対処】が大事かと。
ただ【小さな意識】ができる人は、【場面】でマジで【良い結果】になりやすいです。
ここを【時期】のうちに整えておくと、その後が楽になります。

「【ネガティブな評価】」と思われがちな【対象】、下にn個...

【リプ①】〜【リプ⑦】
　見出し
　実際、【具体的な場面】で【セリフ】と返した方がいました。
　【その行動自体は否定しない】。ただ見られてるのは【本当の評価軸】。
　【入社後の画が浮かぶ】んですよね。
　【どうすれば評価が上がるか】。
```

## 相性の良いテーマ
- 「能力はあるのに落ちる」系のテーマ（原因が態度・伝え方・順番にあるもの）
- 項目が5〜7個に分解でき、それぞれに実際の場面がつくテーマ
- 読者が薄々気づいているが言語化されていないテーマ

## 相性の悪いテーマ
- 具体的な場面が出せないテーマ（リプが抽象論になって失速する）
- 3個以下しか出ないテーマ（連載の形にならない）

## 文体・見た目のメモ
- 本編：400〜600字。リプ：各150〜250字
- リプは必ず番号つきの見出しから始める
- 断定と保留を混ぜる（「〜かと」「〜なんですよね」）
- 絵文字なし

## バリエーション

### A. データ提示型（2026-09-23 追加・参考投稿①）
リプの使い方を変えた派生。骨格（本音の問題提起 → リプで連載解説）は同じ。

- **リプ1で先に結論（企業リストなど）を渡し**、「改めて方法を...」で本編へ戻す。
  待たされる不満を先に潰せるので、離脱が減る
- リプ2に**外部の事実・他社事例・調査データ**を並べ、「今の常識が変わりつつある」と示す
- リプ3で判断基準、リプ4で確認手順、と**抽象→具体**の順に降ろす
- 締めは「保存して、次の面接で使ってください」と保存を直接促す
- ⚠️ 外部データを使う型。**出典のない数字は書かない**。生成時は `【　】` にして本人が確認して埋める
