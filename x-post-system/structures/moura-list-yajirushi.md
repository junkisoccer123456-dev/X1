# 構文名：網羅リスト（↓連結）型

## この構文が読まれやすい理由
- 1行目が「〇〇まとめ↓」だけ。前置きがなく、読む前に中身が分かる。
- ↓ で20項目前後を縦に連結すると、タイムラインで画面を占有し続ける。**量そのものが価値**として伝わる。
- 解説が一切ないので読む負荷がない。代わりに「全部は答えられない」という自覚が残り、保存される。
- 順番に意味があるため（選考の流れ順、難易度順）、上から読むだけで全体像が入る。
- 発信者が「毎回聞いている側」なので、網羅性に説得力が出る。立場と内容が一致している型。

## 基本構造
```
①「【対象】が【場面】で【何】まとめ↓」の1行
 ↓
②項目1
 ↓
③項目2
 ↓
（…15〜25項目。解説なし。順番は流れ順か難易度順）
 ↓
④最後の項目で締める（まとめの一言は入れなくてよい）
```

## 抽象テンプレート
```
【対象読者】が【場面】で【聞かれること／やること】まとめ↓

【項目1】
↓
【項目2】
↓
（…15〜25項目）
↓
【最後の項目】
```

## 相性の良いテーマ
- 項目が15個以上出せて、しかも順番があるテーマ（面接の質問、選考の流れ、準備の手順）
- 読者が「全部は分からない」と自覚するテーマ
- 1項目が1行で書けるテーマ

## 相性の悪いテーマ
- 項目が5個程度しか出ないテーマ（網羅感が出ず、ただのリストになる）
- 各項目に説明が要るテーマ

## 文体・見た目のメモ
- 文章量：項目数で決まる。15〜25項目
- ↓ は行単体で置く
- 絵文字なし。CTAも基本なし（入れるならリプへ）
- 解説を足したくなるが、足さないほうが効く

## バリエーション

### A. 理由列挙型（2026-09-23 追加・参考投稿⑩）
↓ ではなく「・」で20〜25項目を並べる派生。項目が事実ではなく**主張・理由**になる。
網羅されるほど説得力が増すのがポイント。並び順は読者の関心が深くなる順にする
（ビジネスモデル → 働き方 → キャリア）。
1項目1行で完結させること。説明を足すと20行以上のリズムが破綻する。
⚠️ 「年収800万が現実的」のような数値の主張は、出典がないと書けない。
参考：`../references/2026-09-23-nori/10-SaaSをすすめる理由25.md`

### B. カテゴリ付き質問網羅型（2026-09-23 追加・参考投稿④）
↓ ではなく **■カテゴリ見出し＋○項目** で並べる派生。質問リストに向く。

- 「これ以外に聞かれないです」という**言い切り**が価値になる（網羅性の保証）
- 質問は実際に使っている表現のまま書く。整えすぎると現役感が消える
- 一部の項目にだけ子項目（- で始まる追加質問）を付けると、単調さが消える
参考：`../references/2026-09-23-kei/04-質問網羅.md`

### C. 回答例リプ連載型（2026-09-24 追加・参考投稿①）
網羅リストの前に「問題提起」を置き、リストのあとに「回答例をまとめた」と宣言して、
**リプで1項目ずつ回答例（そのまま使える文）を出す**派生。
リストだけで終わらせず、不安を煽ったぶんの解決策をリプに置くのが核。

```
①感情の漏れ（衝撃すぎました...）＋権威フック
 ↓
②問題提起（準備せずに来る人がいる → ほぼ落ちる → もったいない）
 ↓
③「聞かれることは大体決まってます↓↓」
 ↓
④項目を ↓ で連結（10〜25個。選考の流れ順。該当者のみの項目には注記を付ける）
 ↓
⑤「準備しなければ落ちます。回答例をまとめたので参考に↓↓」で切る
 ↓
⑥【リプ(n/N)】項目名 ＋ カギ括弧の回答例（2〜4文／事実→打ち手→現在の状態）
```
回答例の固有名詞・数字はプレースホルダ（〇〇／△△／〇年／〇〇万円）にする。
読者が自分の情報を入れるだけで使える状態にしておくのが、保存される条件。
参考：`../references/2026-09-24-kei/01-面接25問-回答例.md`

### D. 最後の1つを伏せる型（2026-10-05 追加・参考投稿⑧）
n個のうち**n-1個までを並べ、最後の1つだけを伏せて引く**派生。

```
①「間違った〇〇の常識」などの見出し1行
 ↓
②①❷③❹⑤❻⑦❽⑨ と、白丸と黒丸を交互にして9項目を並べる（解説なし）
 ↓
③「9割が勘違いしてる、今すぐ捨てるべき〇〇❿は…」で切る
 ↓
④❿＋その1項目だけ解説（100〜200字）
 ↓
⑤CTA
```
効いているのは番号の付け方。白丸（①③⑤⑦⑨）と黒丸（❷❹❻❽）を交互にすると、
見た目にリズムが出て、同じリストでも最後まで目が流れる。
最後の1つだけ解説するので、情報量を抑えたまま主張が立つ。

### E. 囲み数字n選型（2026-10-05 追加・参考投稿⑩）
↓ の連結をやめて、囲み数字（①〜⑪）で一行ずつ並べる。解説も締めもなし。
見出しに【】を入れて「言われないこと」を強調すると、リストだけで成立する。
項目数は10〜12が読みやすい。

```
【権威づけ】、
【相手】が絶対に言わない【 【テーマ】n選 】

① 【項目】
② 【項目】
③ 【項目】
…
⑪ 【項目】
```

囲み数字と項目の間は半角スペース1つ。
項目は「〜される」「〜で決まる」など、**読者が受け身になる言い方**で揃えると
「知らないと損する」感が出る。締めを付けないほうが保存されやすい。

### F. 権威フック＋傾向n選＋CTA型（2026-10-05 追加・参考投稿③）
バリエーションE（囲み数字n選）に、**冒頭の権威フック**と**末尾のCTA**を付けた形。
「〇〇する人の傾向」のように、読者が自分を確認したくなる見出しにする。

```
【権威づけ】ぼくが思う
【テーマ】する人の傾向。

❶【項目】
❷【項目】
❸【項目】
❹【項目】
❺【項目】
❻【項目】
❼【項目】

誰に相談するか迷ったら...↓
【CTA】
```

項目は7個前後。E（11個）より少なくして、1項目を長め（20〜30字）にすると読みやすい。
囲み数字は ❶❷❸ の黒丸系で揃える（①②③と混ぜない）。

### G. 囲み数字→4本リプ小出し型（2026-10-25 追加・参考投稿❹）
Eの囲み数字n選に、**各項目へ「→」1行の解説**を付け、**4本のリプで3項目ずつ小出し**にする派生。
本文は①〜③を出して、④の解説だけ `→◯◯◯` で伏せて「続く↓↓↓」。

```
①【情報源】から分かる【テーマ】⓬選は、、
 ↓
②①【項目】
　→【1行の解説。表記のマジックや裏を暴く】
　（②③も同じ形）
 ↓
③④【項目】
　→◯◯◯
　続く↓↓↓
 ↓
④【リプ1】④の解説から再開し、④⑤⑥ →「まだまだ続く↓↓」
 ↓
⑤【リプ2】⑦⑧⑨ →「↓↓↓」
 ↓
⑥【リプ3】⑩⑪⑫ →「最後に↓↓」
 ↓
⑦【リプ4】原則への一般化2行＋CTA
```

- 伏せ方が独特。項目名は出して**解説だけを `◯◯◯` にする**ので、
  「何が書いてあるんだ」という引きが項目名の具体性で強まる
- 引きの言葉を毎回変える（続く↓↓↓ → まだまだ続く↓↓ → ↓↓↓ → 最後に↓↓）
- →の解説は**命令形か断定**で終える（「騙されるな」「論外」）。説明口調にすると12個が重くなる
- リプ4は項目に戻らず、情報源の読み方そのものを1段上げて締める
- ⚠️ 「120日未満は要注意」のような基準値を出すときは、
  法令や公的統計で確認できるものに限る。社内の体感値は書かない
参考：`../references/2026-10-25-nori/04-求人票12選リプ連載.md`
