# 構文名：網羅リスト（↓連結）型

## この構文が読まれやすい理由
- 1行目が「〇〇まとめ↓」だけ。前置きがなく、読む前に中身が分かる。
- ↓ で20項目前後を縦に連結すると、タイムラインで画面を占有し続ける。**量そのものが価値**として伝わる。
- 解説が一切ないので読む負荷がない。代わりに「全部は答えられない」という自覚が残り、保存される。
- 順番に意味があるため（選考の流れ順、難易度順）、上から読むだけで全体像が入る。
- 発信者が「毎回聞いている側」なので、網羅性に説得力が出る。立場と内容が一致している型。

## 基本構造
```
①「【対象】が【場面】で【何】まとめ↓」の1行
 ↓
②項目1
 ↓
③項目2
 ↓
（…15〜25項目。解説なし。順番は流れ順か難易度順）
 ↓
④最後の項目で締める（まとめの一言は入れなくてよい）
```

## 抽象テンプレート
```
【対象読者】が【場面】で【聞かれること／やること】まとめ↓

【項目1】
↓
【項目2】
↓
（…15〜25項目）
↓
【最後の項目】
```

## 相性の良いテーマ
- 項目が15個以上出せて、しかも順番があるテーマ（面接の質問、選考の流れ、準備の手順）
- 読者が「全部は分からない」と自覚するテーマ
- 1項目が1行で書けるテーマ

## 相性の悪いテーマ
- 項目が5個程度しか出ないテーマ（網羅感が出ず、ただのリストになる）
- 各項目に説明が要るテーマ

## 文体・見た目のメモ
- 文章量：項目数で決まる。15〜25項目
- ↓ は行単体で置く
- 絵文字なし。CTAも基本なし（入れるならリプへ）
- 解説を足したくなるが、足さないほうが効く

## バリエーション

### A. 理由列挙型（2026-09-23 追加・参考投稿⑩）
↓ ではなく「・」で20〜25項目を並べる派生。項目が事実ではなく**主張・理由**になる。
網羅されるほど説得力が増すのがポイント。並び順は読者の関心が深くなる順にする
（ビジネスモデル → 働き方 → キャリア）。
1項目1行で完結させること。説明を足すと20行以上のリズムが破綻する。
⚠️ 「年収800万が現実的」のような数値の主張は、出典がないと書けない。
