# 構文名：対応表途中切り型

## この構文が読まれやすい理由
- **行の途中で切る**のが核。最後の行の矢印の先を空白のまま終えるので、
  「続きは↓」のような言葉を一切使わずにリプを開かせられる。視覚的な未完成がそのまま引きになる。
- 1行1件のBefore▶Afterなので、読者は**自分の左側を探す読み方**になる。自分ごと化が自動で起きる。
- 説明が一切ない。読む負荷がゼロで、保存される。
- 業界・職種レベルに丸めてあるので、個人が特定されず、そのぶん当てはめやすい。
- 解説を書かないぶん、リプ欄に「自分はこうでした」が集まりやすい構造になっている。

## 基本構造
```
①見出し1行（対象と内容を確定させる。例：20代中盤の転職でキャリアアップした事例）
 ↓
②列ヘッダ【Before】【After】（全角スペースで列を揃える）
 ↓
③・Before　▶ After を1行1件で並べる（業界のかたまりで並べる。説明なし）
 ↓
④最後の行は右側を空白にして切る（・〇〇　▶ で終える）
 ↓
⑤【リプ】切った行をもう一度書き直してから、続きを並べる。締めもCTAもなし
```

## 抽象テンプレート
```
【対象】の【内容】事例

【Before列の名前】　　　　　【After列の名前】
・【項目1】 　　▶ 【結果1】
・【項目2】 　　▶ 【結果2】
・【項目3】 　　▶ 【結果3】
・【項目4】 　　▶ 【結果4】
・【項目5】 　　▶

（リプ）
・【項目5】 　　▶ 【結果5】
・【項目6】 　　▶ 【結果6】
（…続き）
```

## 相性の良いテーマ
- Before と After の対応で語れるテーマ（転職前後、職種転換、制度の言い換え）
- 読者が自分の左側を探せるテーマ
- 業界・職種レベルに丸めても価値が残るテーマ

## 相性の悪いテーマ
- 1件ごとに説明が必要なテーマ（説明を入れると型が崩れる）
- 対応が1対1にならないテーマ
- 個人が特定される粒度でしか語れないテーマ

## ⚠️ 運用上の注意
- 事例を出す型なので、**実在の個人が特定できる粒度にしない**。業界・職種レベルに丸める。
- 支援人数などの実績は、アカウントファイルに登録されている範囲だけ使う。
- 対応が「必ずそうなる」と読まれないよう、見出しで「事例」と明示する。

## 文体・見た目のメモ
- 本文は約120字、リプは約130字。短い
- 矢印は ▶。列の区切りとして見やすい
- 全角スペースで列を揃える（スマホでも崩れにくい幅に収める）
- 業界のかたまりで並べる（金融系→コンサル→商社→メーカー のように）
