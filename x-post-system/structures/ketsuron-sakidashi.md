# 構文名：結論先出し警告型

## この構文が読まれやすい理由
1行目で結論を言い切るので、読む前に「何の話か」が確定する。
しかも結論が**固有の言葉**（少人数職場／フィラー）なので、知っている人も知らない人も止まる。

そのあとの箇条書きは、結論を支える材料でしかない。読者は答えを先に知っているので、
箇条書きを「自分に当てはまるか」のチェックリストとして読む。これが保存される理由になる。

締めで「つまり、〜した時点で詰みます」のように言い切るので、読んだあとに行動が1つ決まる。

## 基本構造
```
①結論を1語〜1フレーズで先出し（「避けてほしい職場は”〇〇”」）
 ↓
②見分け方を1行（「求人に『〇〇』の記載がある場合は要注意」）
 ↓
③・根拠／具体例を箇条書き（3〜15項目。解説は1行まで）
 ↓
④「つまり、〜」で意味づけ（言い換えて1文で落とす）
 ↓
⑤特に〜は〇〇なので慎重に（対象を絞って注意喚起）
```

## 抽象テンプレート

```
【場面】で絶対に避けてほしい【対象】は”【固有の言葉】”

例えば【見つけ方】に「【サインになる表現】」などの記載がある場合は要注意

・【根拠1】
・【根拠2】
・【根拠3】

つまり、【何が起きた時点でどうなるか】。
特に「【さらに危ない条件】」は、【リスク】が高すぎるので慎重に。
```

## 相性の良いテーマ
- 言葉として名前が付く落とし穴（少数精鋭／アットホーム／幹部候補）
- 読者が自覚していない癖・習慣（話し方、書き方、聞き方）
- チェックリストとして使えるテーマ

## 相性の悪いテーマ
- 結論を1語に圧縮できないテーマ（冒頭が長いとこの型は死ぬ）
- 根拠が1つしかないテーマ（箇条書きが埋まらない）

## 文体・見た目のメモ
- 文章量：150〜300字
- 結論の固有名詞は引用符（”〇〇”）かカギ括弧で囲んで浮かせる
- 箇条書きは解説なしか1行まで。長くすると結論の圧が下がる
- 締めは言い切る（「詰みます」「頭に入ってこない」）
- 絵文字なし

## バリエーション

### A. 避けるべき対象＋根拠3つ型（2026-10-05 追加・参考投稿④）
原型。結論を1語で出して、根拠を3つに絞る。
項目を増やさず、代わりに「特に〇〇は慎重に」で対象を絞り込んで終える。

### B. 具体語連打型（2026-10-05 追加・参考投稿⑥）
権威フック＋「9割の人が気づかない〇〇はこれ。」から入り、「結論」とラベルを打ってから
カギ括弧で一言。そのあと**具体的な言葉を10〜15個連打**する。

```
【権威づけ】が、9割の人が気づかない【場面】で【結果】になる理由はこれ。

結論
「【固有の言葉】（【カッコで補足説明】）」

・「【具体語1】」
・「【具体語2】」
（…10〜15個）

【固有の言葉】が多すぎると
【相手】側は
【何が起きるか】。
```

連打する言葉は、読者が**自分でも言っている自覚がある**ものを選ぶ。
「言われてみれば自分も」が起きると、そのまま保存される。
締めは短く改行で落とすと、リストの圧が残る。
