# 構文名：問いかけ名指し記事型

## この構文が読まれやすい理由
冒頭が【転職活動中の方へ】のように**読者を名指しする見出し**なので、該当する人だけが止まる。
そのうえで「〜で終わっていませんか？」と**読者がいまやっている行動**を当てにいくので、
問いかけの時点で自分の話として読み始める。

本題は「実は、その先に取れる情報があります」のように、**読者が止まっている場所の1歩先**を示す形。
知識を足すのではなく、同じ行動の続きを教えるので、長文でも最後まで読まれる。

途中に**そのまま使える質問文例**が入るのが一番効く。読み終わったあとに行動が決まるので保存される。
締めは「落ちたら〜／通ったら〜」のような対句で原則に落とす。

## 基本構造
```
①【読者を名指しする見出し】
 ↓
②※前置き（「ぜひ一度読んでいただけたら嬉しいです」）
 ↓
③権威づけ1行
 ↓
④読者の行動を問いで名指し（「〜と聞いて終わっていませんか？」を2つ並べる）
 ↓
⑤「実は、どちらもその先に取れる情報があります」
 ↓
⑥本題の主張（「結果だけではなく、その中身まで聞いてほしい」）
 ↓
⑦確認すべき項目を箇条書き（4〜6個）
 ↓
⑧「同じ〇〇でも意味が全然違う」＋ケース分岐を2つ
 ↓
⑨【見落とされがちな点】を宣言（カッコで強調）
 ↓
⑩そのまま使える質問文例（カギ括弧で2〜3個）
 ↓
⑪自己開示（「僕も〜していました」）
 ↓
⑫さらに踏み込める質問（「できれば〜まで聞けるとさらにいい」）
 ↓
⑬原則に一般化（「〇〇は〜のためだけに使うものではありません」）
 ↓
⑭対句（「落ちたら〜／通ったら〜」）
 ↓
⑮【1文の結論】
 ↓
⑯CTA
```

## 抽象テンプレート

```
【【読者の状態】の方へ】
※【該当者への前置き】、ぜひ一度読んでいただけたら嬉しいです。

【権威づけ】、これは知っておいてほしい。
【場面1】で「【よくある言葉】」と言われて、「【読者がする質問】」と聞いて終わっていませんか？
逆に【場面2】で「【よくある言葉】」と言われて「【読者の反応】」で終わっていませんか？
実は、どちらもその先に取れる情報があります。

せっかく【手段】を使うなら、【表面の情報】だけではなく、その「中身」まで聞いてほしい。
例えば【場面1】のとき。「【浅い質問】」だけではなく、

・【確認項目1】
・【確認項目2】
・【確認項目3】
・【確認項目4】
・【確認項目5】
できる範囲で、ここまで確認してもらう。
というのも同じ「【結果の名前】」でも意味が全然違うんです。

「【ケースA】」なら、【解釈A】かもしれない。
でも、【ケースB】なら、これは【行動B】した方がいい。

【情報の使いみち】。そして、ここは意外と見落とされがちですが、
【【逆のケースこそ聞いてほしい】】

「【よくある言葉】」と言われたら、「【質問文例1】」「【質問文例2】」
と聞いてみてください。

【実際はどうなっているかの説明】。

僕も【自己開示】、【何をしていたか】まで【相手】に聞いていました。
ここが分かるだけでも、【次の行動】はかなり変わります。

できれば、「【さらに踏み込む質問1】」「【さらに踏み込む質問2】」まで聞けるとさらにいい。

【手段】は「【狭い使い方】」だけに使うものではありません。【なぜその先が取れるのか】。
【ケースA】なら「【問い1】」
【ケースB】なら「【問い2】」
【どちらも】、ただの結果で終わらせない。【【1文の結論】】
これ、【領域】では結構大事です。

【CTA】
```

## 相性の良いテーマ
- 読者が「結果だけ受け取って終わっている」場面（選考結果、評価面談、1on1、面接の感触）
- 聞き方を変えるだけで情報量が変わるテーマ
- そのまま使える質問文例が書けるテーマ

## 相性の悪いテーマ
- 問いかけで名指しできないテーマ（読者の行動が特定できない）
- 文例が作れないテーマ（この型は文例が本体）

## 文体・見た目のメモ
- 文章量：1本1,200〜2,000字（長文記事）
- 見出しは【】で囲む。本文中の強調も【】を使う（アスタリスクは使わない）
- 質問文例はすべてカギ括弧。読者がコピーして使える形にする
- 箇条書きは・を使い、解説を足さない
- 1段落は3〜4行まで。空行を多めに取る
- 絵文字なし

## バリエーション

### A. 常識否定→基準の置き換え型（2026-10-05 追加・参考投稿⑨）
問いかけではなく、**読者が持っている常識を名指しして否定する**形から入る派生。

```
【【読者の目的】の方へ】
「【よくある常識を具体的な形で】」この考え方一度捨ててください。

【相談の場面】をしていると、
「【よくある発言1】」
「【よくある発言2】」という話をよく聞きます。

でも、【対象】は「【その常識の計算式】」で決まるものではありません。
【決める側】が見ているのは「【読者が思っていること】」だけではなく、

・【判断要素1】
・【判断要素2】
（…6〜9個）

こうした要素を踏まえて、【どう判断するか】。

例えば、【同じ条件でも違いが出る例】。

逆に怖いのは、【読者が損をするケース】です。
【具体的な説明】。
そこで「【常識の計算式】」を基準にしてしまえば、【どう損をするか】。

だから、【行動】を決める前にやってほしいことがあります。まず、【手順1】。
【手順2】。そして、【手順3】。

【手段】を使うなら、「【浅い質問】」だけでは少し足りません。
「【質問文例1】」
「【質問文例2】」
「【質問文例3】」
ここまで聞いてみてください。

【関連する別の場面】も同じです。
「【浅い言い方】」ではなく、【正しい考え方】。

【領域】で見るべきなのは、「【常識の指標】」ではありません。見るべきなのは、
「【本当の指標】」【理由】。

【常識】を基準に決めるのではなく、まず【本当の指標】を知る。【目的】ならここからです。

【CTA】
```

原型（⑧）との違いは入口だけで、後半（項目リスト → 具体例 → 質問文例 → 対句 → 締め → CTA）は同じ。
**常識を「具体的な数字や言い方」の形で引用してから否定する**のがこの派生の勘所。
「〇〇という考え方」と抽象で否定すると刺さらない。
