# 構文名：リスト提示→リプ回収型

## この構文が読まれやすい理由
- **1行目で読者を名指しする**ため、該当する人だけが確実に立ち止まる。万人向けの投稿より刺さり方が深い。
- 箇条書きが縦に10行以上並ぶと、タイムライン上で**画面を占有する「情報の塊」**になる。中身を読む前に「これは有益そうだ」と判断され、スクロールが止まる。
- リストに解説を付けないので、読む負荷がほぼゼロ。読者は「全部は覚えられない」と感じ、**保存（ブックマーク）の動機だけが残る**。
- 中盤で「よくある失敗」を指摘することで、リストを眺めただけの読者に「自分はできていないかも」という引っかかりを作る。
- 本文が「〜が分からない人は、」で**言い切らずに終わる**。未完了の状態でリプに続くため、読者は自然にリプを開く。
- 宣伝・フォロー誘導を本文から完全に排除しているため、押しつけ感がない。**CTAをリプに逃がす**ことで、本文は最後まで「善意の情報提供」に見える。

## 基本構造
```
①読者を名指し＋いま考えるべき状況の提示
 ↓
②結論としての推奨行動（1行）
 ↓
③リスト（8〜16行／解説なし／縦に並べる）
 ↓
④よくある失敗の指摘（「〜する人が多い」）
 ↓
⑤「〜が分からない人は、」で文を切る（言い切らない）
 ↓
⑥【リプ】フォロー誘導＋アカウントの価値説明＋再訪の促し
```

## 抽象テンプレート
```
【対象読者】は、
【タイミング】に【推奨行動】も見ておきましょう。

【項目1】
【項目2】
【項目3】
（…8〜16行。解説はつけない）

【よくある失敗】する人が多いので、【判断基準】が分からない人は、

【リプ】
ぼくのアカウントをフォローしておいてください。

【ターゲット】に向けて、【発信内容】を【立場・視点】から発信してるので、
定期的に覗きに来てください。
```

## 相性の良いテーマ
- 選択肢・候補が多く、**列挙するほど価値が出る**テーマ（企業群、職種、質問、NG表現、チェック項目）
- 読者が「自分は全部知らない」と自覚しやすいテーマ
- 一つひとつに長い説明が要らないテーマ（単語・短文で伝わるもの）
- 保存して後で見返したくなるテーマ

## 相性の悪いテーマ
- 因果や手順の説明が必要なテーマ（リストにすると意味が通らない）
- 項目が3〜4個しか出ないテーマ（情報の塊にならず、構文の強みが消える）

## 文体・見た目のメモ
- 文章量：リストを含めて300〜500字。リストがある場合は140字を超えてよい
- 1行の長さ：リスト部分は単語〜20字程度。地の文は1文を短く
- 改行/空行：導入とリストの間、リストと締めの間に空行1つ。リスト内は改行のみで詰める
- 絵文字：使わない
- CTA：本文には入れない。必ずリプに置く

## 注意点
- 企業名・サービス名を列挙する場合、募集状況や条件は変わるため**断定しない**。
  「受け皿として名前を挙げておきます」程度の温度にし、投稿前に最新情報を確認すること。
- 数字（割合・平均年収など）は、確かな出典がない限り書かない。

## バリエーション

### A. NGリスト型
リストを「NG例」で統一する型（NGリスト提示→言い換え提示→リプ回収）。比較を入れたいときに使える。

### B. リスト分割型（2026-09-22 追加／参考投稿⑤）
リストを**本文とリプに分割**する派生。骨格は同じだが、以下が違う。

- 本文にリストの前半（5個）→ リプ1に後半（6個）を置く。続きが気になるのでリプが開かれる
- 1行目を「〜を狙うなら、、、」で引っぱり、2行目からすぐリスト
- リスト内の1項目にだけ `←意外と知られてない` のようなツッコミを付ける（全部には付けない）
- リプ1でリスト後半＋解説＋根拠（「肌感ですが、実務3年あれば十分に狙えるかと」）
- リプ2でフォロー誘導（CTAはここだけ）

```
①読者名指し＋「〜なら、、、」で引っぱる
 ↓
②リスト前半（5個前後／1つだけツッコミを添える）
 ↓
③【リプ1】リスト後半（6個前後）＋なぜオススメかの解説＋根拠
 ↓
④「〜が分からない人は、」で切る
 ↓
⑤【リプ2】フォロー誘導
```

同じカテゴリ（グループ企業など）で縦に揃えると説得力が増す。
参考：`../references/2026-09-22-リスト提示→リプ回収型-バリエーション.md`

### C. リスト単体型（リプなし／2026-09-23 追加・参考投稿⑤⑧）
リプも解説も付けない最小構成。2行の見出し＋リストだけで成立させる。

- リストの粒度が価値になるので、**20項目以上**並べる（企業名なら25社前後）
- 解説を足さない。足すとリストの圧が下がる
- リストの中身は企業名でなくてもよい。**人物条件**（「声が明るい」「KPIを自然に使える」）でも成立する
- 条件リストの場合、**下にいくほど専門的になる順番**にする。
  前半で「自分もいけそう」、後半で「ここは足りない」と気づかせる
- CTAなしで終われる型。保存だけを狙う
参考：`../references/2026-09-23/05-働きやすいSaaS25社.md` / `../references/2026-09-23/09-IS面接で落ちない人.md`

### D. 3社横並び型（2026-09-23 追加・参考投稿②）
バリエーションBの派生。社名を**3つずつ横並び**にして改行すると、同じ社数でも密度が上がる。
リプの最後は、フォロー誘導ではなく「入口はこの2職種」のような**実用の結論**で締めてもよい。
参考：`../references/2026-09-23/02-未経験でも入れる企業リスト.md`

### E. 2列並列型（2026-09-23 追加・参考投稿②）
2つのカテゴリを**左右2列**に並べる派生。同じ行数でも情報量が倍に見える。
カテゴリ見出しに番号記号を付けて立てる。全角スペースで列を揃えるため、投稿前にスマホ表示の確認が必要。
参考：`../references/2026-09-23-nori/02-資格2列リスト.md`

### F. カテゴリ分割型（2026-09-23 追加・参考投稿⑧）
カテゴリ別のリストを**途中のカテゴリで切ってリプに続ける**派生。項目単位ではなくカテゴリ単位で引っぱる。
リプでリストを完成させた直後に、**リスト自体を相対化する本音**（「社名ではなく配属部署で8割決まる」）を置くと深さが出る。
さらにリプを1本足して、読者が自分で判断するための質問を3つ渡すと、丸投げで終わらない。
参考：`../references/2026-09-23-nori/08-業界別ホワイト企業.md`

### G. チェックボックス型（2026-09-23 追加・参考投稿①）
リストの記号を **□（チェックボックス）** にする派生。読者が自己採点を始めるので保存率が上がる。

- 1項目は20〜50字。「できている／できていない」が判定できる粒度で書く
- 項目数は5〜8個。多すぎると採点が面倒になる
- 冒頭は権威フック＋「これですね↓」程度の短い導入だけにする
参考：`../references/2026-09-23-kei/01-チェックリスト.md`

### H. 長文一文リスト型（2026-09-23 追加・参考投稿⑦）
1項目を**40〜60字の長い一文**にし、理由まで書き切る派生。項目は5つ程度に絞る。
タイトルをカギ括弧で囲むと、投稿全体が記事の見出しのように見える。
読者が自社・自分と照合できるので、短いリストでも刺さる。
参考：`../references/2026-09-23-kei/07-特徴リスト.md`
