# 構文名：技法カタログ型

## この構文が読まれやすい理由
- **技法に名前をつける**のが核。名前がついたものは覚えられ、人に説明され、引用される。
- 各項目が「名称 → 何をする技か → なぜ効くか → 例文」で完全に統一されているため、読むリズムが一定。
- 例文がそのまま使えるので、保存する理由が明確になる。「あとで使う」が発生する。
- 冒頭で「そのまま使えるので」と用途を宣言すると、読む前に価値が伝わる。
- 5項目前後なので、リストとしては重くないのに、1項目の密度が高い。

## 基本構造
```
①「〇〇するときの【技法】n選」＋用途の宣言（そのまま使えます）
 ↓
②【技法1の名前】
　 何をする技か（1行）
　 なぜ効くか（1行）
　 例：「そのまま使える文例」
 ↓
③〜⑥ 同じ構造で残りの技法
```

## 抽象テンプレート
```
【場面】で使える【技法の総称】n選。そのまま使えるのでぜひ参考に。

●【技法1の名前】
【何をする技か】
【なぜ効くか／相手にどう伝わるか】
例：「【そのまま使える文例】」

●【技法2の名前】
（同じ構造で繰り返す）
```

## 相性の良いテーマ
- 言い方・聞き方・伝え方で差がつくテーマ
- 例文が書けるテーマ
- 技法が4〜6個に分けられるテーマ

## 相性の悪いテーマ
- 例文が出せないテーマ（抽象論になって価値が落ちる）
- 項目が10個以上あるテーマ（カタログではなくリストになる）

## バリエーション

### A. 判別サイン型（2026-09-23 追加・参考投稿⑨）
例文の代わりに、**「それが何を意味するか」の翻訳2行**を置く派生。
求人票や上司の発言など、表に出ている表現を読み替えてあげる構造。

```
①【判別したい対象】にしか出てこない表現はこちら
 ↓
②① 【表現・特徴】
　 【それが意味すること】
　 【だから何が言えるか】
 ↓
③〜⑩ 同じ構造（10項目まで増やせる）
```
読者はそのままチェックリストとして使える。項目は10個まで増やしてよい。
参考：`../references/2026-09-23-kei/09-サイン10項目.md`

### B. 名称＋定義＋効果の3段型（2026-11-04 追加・参考投稿２）
原型の4段（名前→何をする技か→なぜ効くか→例文）から**例文を落とした3段**の派生。
記号は **⚫︎**、見出しの末尾に **↓↓** を付ける。

```
【場面】で便利な【技法の総称】n選↓↓

⚫︎【技法1の名前】
【何をする技か（手順や頭文字を1行で）】
【なぜ効くか／相手にどう伝わるか（1行）】

⚫︎【技法2の名前】
（同じ3段で繰り返す）
```

- 技法名は**略称や頭文字で名前がついているもの**だと強い（STAR法・PREP法 など）。
  名前がないものには付ける
- 1項目3〜4行。例文を落とすぶん項目数を増やせるが、**5個前後**が読みやすい
- 権威づけもCTAも付けない。見出し1行で入って、最後の項目で終わる
- 原型（A含む）との違いは「例文がない」ことだけなので、
  そのまま使える文例を渡したいときは原型、覚えて使う型を渡したいときはBを選ぶ
参考：`../references/2026-11-04-kei/00-構文リスト.md`

## 文体・見た目のメモ
- 文章量：技法5つで500〜700字／判別サイン10項目で600〜800字
- 技法の名前は「〇〇法」「〇〇質問」など、短く言い切る
- 例文はカギ括弧で囲む
- 絵文字なし（項目の記号は●や①などを使う）
