# 構文名：面接官の本音暴露→見るポイント→記事リプ誘導型

## この構文が読まれやすい理由
- 「この質問で、面接官は〇〇を聞いていません」と、質問の裏側を断定するので、受験者が知らない視点が手に入ると感じて止まる。
- 立場（人事部長）から「採用する側の本音」を話すので、評価する側の目線という権威性がそのまま効く。
- 落ちる答え／受かる答えを並べて対比するので、自分がどちらかをすぐ確認できる。
- 全部は書かず、「全7問は記事に」と送る。保存したくなる情報の続きが記事にある形になる。

## 基本構造
```
①「この質問で、面接官は〇〇を聞いていません」の断定フック
 ↓
②採用する側の立場から、見ているポイントを1文で
 ↓
③落ちる人の答え（セリフ）
 ↓
④受かる人の答え方（構造）
 ↓
⑤1文で言い切って着地
 ↓
【リプ】全7問と見られているポイントは記事にまとめた
```

## 抽象テンプレート
```
「【質問】」。この質問で、面接官は【表面の意図】を聞いていません。

【立場】ですが、ここで見ているのは「【本当に見ているポイント】」です。

落ちる人はこう答えます。「【NGセリフ】」。

受かる人は【答え方の構造】で話します。【具体例】。

【一言の着地】。

【リプ】
【質問群】と、面接官が見ているポイントを、ここにまとめています。
```

## 相性の良いテーマ
- 面接官・採用側しか知らない評価基準があるテーマ
- 質問ごとに「見られているポイント」が決まっているテーマ

## 相性の悪いテーマ
- 評価基準が会社ごとに大きく違うテーマ（言い切ると嘘になる）

## 文体・見た目のメモ
- 文章量：450〜520字
- 数字・統計は使わない（質問の数「7つ」は記事の事実）
- 落ちる例はセリフで、受かる例は構造で書く
