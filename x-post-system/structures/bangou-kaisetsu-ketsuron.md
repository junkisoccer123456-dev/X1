# 構文名：番号付き項目＋一言解説＋結論畳み型

## この構文が読まれやすい理由
- 冒頭が「権威づけ＋これだと思う」で終わる。**断定だが押しつけない**言い方なので、
  長文の入り口として角が立たない。
- 項目が **1. 2. 3.… と通し番号**なので、残りの量がスクロールバーで見える。
  「あと何個あるか」が分かる状態は、読者が読み切る判断をしやすい。
- 1項目が「タイトル（括弧で言い換え）→ 2〜3行の解説」だけ。
  **1項目あたりの読む時間が5秒**なので、15項目あっても重くならない。
- 括弧の中に**別の言い方**を入れている（「論理的思考（ロジカルシンキング）」
  「情報整理の力（抽象化・要約力）」）。同じものを2語で言うと、読者の語彙に引っかかる。
- 解説の中に**逆のケース**を必ず1行入れる（「逆に30代でこれが弱いと、もう改善が難しい」
  「優先順位がつけられない＝仕事ができない人の典型」）。
  褒める側だけでなく落ちる側も書くので、自分ごとになる。
- 項目数が10を超えるので、**「全部やれ」とは読まれない**。
  読者は自分に刺さった3つだけ持ち帰る。これが保存の動機になる。
- 最後に **【結論】** を置いて、15項目を1文に畳む。
  列挙で散らしたものを1行に戻すので、読み終わりがすっきりする。

## 基本構造
```
①権威づけ＋「〇〇はこれだと思う。」（断定だが柔らかい言い切り）
 ↓
②1.【項目名】（括弧で言い換え）
　 【何がどう効くか】1〜2行
　 【逆のケース／できないとどうなるか】1行
 ↓
③2.〜15. 同じ構造で繰り返す（項目数は10〜15）
 ↓
④【結論】
 ↓
⑤15項目を1文に畳む（「大事なのはAじゃなくてB」の形が決まりやすい）
```

## 抽象テンプレート
```
【権威づけ】、
【対象読者】が【動詞】べき【テーマ】はこれだと思う。

1.【項目名】（【言い換え】）
【効く理由】
【逆のケース】

2.【項目名】（【言い換え】）
・【補足1】
・【補足2】
この「【まとめの言い換え】」ができると、【得られる状態】。

…（10〜15項目）

【結論】

【対象読者】で大事なのは、
「【よく言われること】」じゃなく「【本当に必要なこと】」。
```

- 括弧の言い換えは**全項目に付けなくてよい**。付けると密度が上がり、外すとリズムが変わる。
- 解説は1項目2〜3行。4行を超えると15項目が読み切れなくなる。
- 項目の中に**箇条書き（・）を入れるのは2〜3項目まで**。全部に入れると番号が埋もれる。
- 【結論】は必ず「AじゃなくB」か「結局〜に尽きる」のどちらかに寄せる。列挙を1行に戻す役。

## 相性の良いテーマ
- **数を並べることに意味があるテーマ**（身につけるもの／捨てるもの／経験しておくもの）。
  「15個ある」こと自体が情報になる。
- 読者が**全部やる必要がない**テーマ。チェックリストではなく棚卸しとして読ませる。
- 評価する側・見てきた側の立場から語れるテーマ（権威づけが冒頭1行で効く）。

合わないテーマ：
- 手順が決まっていて**順番に意味があるもの**（それはロードマップ型やフロー型のほうが合う）。
- 項目が5個以下で収まるもの（番号の量感が出ないので、技法カタログ型などのほうが合う）。
