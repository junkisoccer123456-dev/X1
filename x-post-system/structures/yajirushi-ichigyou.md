# 構文名：矢印一行解説型

## この構文が読まれやすい理由
- 冒頭が「立場の一言」だけ。年数も人数も出さないのに、権威が伝わる。前置きがないので離脱しない。
- 2行目の見出しに感情語を1語だけ入れる（安心する／痛い／もったいない）。ここで自分ごとになる。
- 項目が5つ。網羅ではなく厳選なので、読み切れて、全部覚えて帰れる。
- 矢印の右が一行。長いと読まれないが、一行なら目が滑らずに全部入る。
- 矢印の中身が「事実の説明」ではなく「相手からどう見えるか」の翻訳になっている。
  ここが他のまとめ投稿との差。読者は評価の基準を受け取ることになる。
- 締めが1行の断定。褒めも脅しもしすぎないので、保存されやすい。

## 基本構造
```
①権威フック（立場を一言）
 ↓
②「〇〇n選」の見出し（感情語を1語入れる：安心する／痛い／損する など）
 ↓
③・項目 → 一行の解説（5つ。矢印の右は必ず1行に収める）
 ↓
④締めの主張1行（逆張り、または両側から挟む一言）
```

## 抽象テンプレート
```
【立場】してますが、
【場面】で【感情語】【対象】5選

・【項目1】 → 【一行の解説】
・【項目2】 → 【一行の解説】
・【項目3】 → 【一行の解説】
・【項目4】 → 【一行の解説】
・【項目5】 → 【一行の解説】

【締めの断定1行】
```

## バリエーション

### A. 評価コメント版（参考投稿①）
矢印の右を「それができると、相手からどう見えるか」にする。
技術や経験の説明ではなく、評価の翻訳を置く。

```
・Git → コンフリクト解消まで話せると強い
・SQL → JOINと索引を語れる人は少ない
```
締めは逆張りの断定（「派手な〇〇より、この5つのほうが刺さります」）。

### B. 定義版（参考投稿②）
矢印の右を「噛み砕いた言い換え」にする。用語集として保存される型。
**項目と矢印を改行で分ける**ので、縦に長くなり、タイムラインでの占有面積が増える。

```
・冪等性 
→ 何回実行しても結果が変わらない性質
```
正確さより伝わりやすさを優先する。比喩を1つ混ぜると効く
（Kubernetes →「その箱を大量に指揮する現場監督」）。
締めは両側から挟む一言（「知っているだけでは評価されないが、説明できないと浅く見える」）。

## 相性の良いテーマ
- 評価の基準を翻訳できるテーマ（何ができると、どう見られるか）
- 知っている前提で使われている用語
- 5つに絞れるテーマ

## 相性の悪いテーマ
- 一行で説明できないテーマ（矢印の右が2行になる時点で型が崩れる）
- 項目が10個以上必要なテーマ（網羅リスト型のほうが向いている）

## 文体・見た目のメモ
- 文章量：Aで120〜180字、Bは改行が多いので150〜220字
- 記号は ・ と → のみ。絵文字なし
- 締めの末尾に「、、、」を使うと口語のトーンが出る（Bで有効）
- CTAは本文に入れない

### C. 解説なし・サイン列挙型（2026-10-05 追加・参考投稿⑨）
矢印の解説を全部落として、項目だけを5行並べる。そのぶん締めを2行に増やし、
個別の項目ではなく**価値観や環境の話に一般化**して終える。

```
【権威づけ】わかった、【テーマ】のサイン

・【サイン1】
・【サイン2】
・【サイン3】
・【サイン4】
・【サイン5】

【一般化した主張1行】。【逆説（居続けることの方がリスク）】かと。
```

項目は「状態」で書く（行動ではなく、そうなっている状態）。
サインなので主語は読者の周囲（上司・会社・同僚）に置くと刺さる。
全体で150〜200字。

### D. チェックリスト＋採用側の本音＋保存推奨型（2026-10-05 追加・参考投稿①）
矢印の右を「**何を見れば判定できるか**」にして、締めを1行の断定ではなく
**採用側の本音2段落＋保存推奨**に差し替える派生。項目は6個まで増やしてよい。

```
①「【対象】の見分け方は覚えておきましょう↓」の1行
 ↓
②【〇〇チェックリスト】の括弧見出し
 ↓
③・【判定したい分類1】 → 【どこを見れば分かるか】
　 ・【判定したい分類2】 → 【どこを見れば分かるか】
　 ・【判定したい分類3】 → 【どこを見れば分かるか】
　 ・【矢印なしの確認項目1】
　 ・【矢印なしの確認項目2】
　 ・【矢印なしの確認項目3】
 ↓
④「【書いている側】から言うと、ここは意外とごまかしが効くポイントです。」
 ↓
⑤具体的なごまかしの例を1つ（「〇〇と書いてあっても中身は△△、なんてのも普通にある」）
 ↓
⑥「面接で必ず確認しておくといいかと。保存しておいて損はないです。」
```

効いているのは3点。
- 前半3項目に矢印を付け、後半3項目は矢印なしの単語にする。**全部揃えないほうが実務のメモに見える**
- 「求人票を書いてる側から言うと」の一言で、チェックリストが裏情報に変わる
- 保存推奨を**最後の半文**だけで済ませる（「保存しておいて損はないです。」）。押し付け感が出ない

矢印の右は「正解」ではなく**確認動作**で書く（「〜が書いてあるか」「〜の文言があるか」）。
