# 構文名：網羅解説記事型

## この構文が読まれやすい理由
- 冒頭が「n個、まとめました。」という**完了報告**から始まる。これから書く記事ではなく、
  すでに揃っている一覧を渡される感じがするので、読む前の心理的コストが低い。
- 「裏側をお話すると、聞かれる質問はほぼ決まっています」で、**読者が漠然と不安だったものを有限にする**。
  無限に見えていた対策範囲が「7個」に縮むので、最後まで読む理由ができる。
- 各項目が必ず「**相手が確認していること**」→「**受かる人の答え方**」の2段で書かれている。
  読者は自分の答えをその場で採点できるので、スクロールが止まる。
- 「新卒とは違う」「〇〇では評価されません」と、**読者がやりがちな答えを先に否定**してから正解を置く。
  だから正解が軽く見えない。
- 記事の最後に全項目を1行ずつ**一覧で再掲**する。ここだけスクショ・保存される。
- 締めが「全部準備できる＝準備しなければならない」という**言い換えで畳む**形。
  煽らずに行動を促せる。
- そのあとに「とはいえ一人でやり切るのは難しいです。。。」と**限界を認めてから**CTAに入る。
  売り込みではなく助言の順番になっているので、宣伝感が出ない。

## 基本構造
```
①「〇〇で必ず【動詞】れる重要なn個の【項目】、まとめました。」＝完了報告のフック
 ↓
②「裏側をお話すると〜はほぼ決まっています。」＝範囲を有限にする
 ↓
③権威づけ＋対比で問題提起（新卒と中途／若手と管理職 など）＋「・・・」で余韻
 ↓
④記事の約束（「全部まとめて、何を見られているかまで解説します」）
　＋『カギ括弧で前置き』（『〜前に必ず読んでほしい内容だったりします』）
 ↓
⑤【項目①】〜【項目n】を同じ4段構成で繰り返す
　　a. 項目名（「質問① 〜」のように番号＋見出し）
　　b. 位置づけ1〜2行（いつ来るか／なぜ来るか／何と違うか）
　　c.「【相手】が〇〇で確認していること」＋カギ括弧で1〜2点に言い切る
　　d.「受かる人の答え方」＋構造（A→B→Cの3段構え）＋そのまま使えるセリフ例
　　※重要な項目には ★ を付ける／NG例は ・ または ● で2〜3行だけ列挙する
 ↓
⑥全項目を一覧で再掲（「① 【項目】　→　【要点1行】」をn行）
 ↓
⑦言い換えで畳む（「つまり、全部準備できるということであり、準備しなければならないという事です。」）
 ↓
⑧断定＋行動の後押し（「〇〇は準備した人だけが通過する場所です。」）
 ↓
⑨限界の提示（「とはいえ、一人でやり切るのは正直難しいです。。。」＋なぜ難しいかを3語で）
 ↓
⑩CTA（「僕の経験上、〜な人ほど〇〇している」→ 推奨 → 導線）
```

## 抽象テンプレート
```
【場面】で必ず【動詞】れる重要なn個の【項目】、まとめました。

裏側をお話すると【場面】で【動詞】れる【項目】は、ほぼ決まっています。

【権威づけ】が、【場面A】には【場面B】と違う「特有の【項目】」があります。
その【項目】に対して、準備できているかどうかで【結果】が決まることがほとんどです・・・

今日は【場面】で必ず【動詞】れる重要な【項目】を全部まとめて、
【何を見られているか】まで解説します。『【場面】前に必ず読んでほしい内容だったりします』

【項目】① 【見出し】

【いつ・なぜ来るか1〜2行】。
ただし、【比較対象】とは求められるものが違います。【比較対象】は【何】を見ています。
【本題】は「【何】かどうか」を見ています。

【相手】が【項目】で確認していること
「【観点1】」「【観点2】」この2点を【短い時間】で判断しています。

受かる人の【項目】の答え方
【A】→【B】→【C】→【D】の順で話します。
【読者がやりがちな答え方】は、【相手】の記憶に何も残りません。
「【そのまま使えるセリフ】」から入り、【制約】にまとめる。これが正解だったりします。

（…②〜n まで同じ4段で繰り返す。重要な項目には ★ を付ける）

【場面】で必ず【動詞】れるn個の重要な【項目】
① 【項目】　→　【要点1行】
② 【項目】　→　【要点1行】
（…n行）

この n個は、ほぼ全ての【場面】で【動詞】れます。
つまり、全部準備できるということであり、準備しなければならないという事です。

【場面】は準備した人だけが通過する場所です。今日この記事を読んだら、
まずは準備に取り掛かってほしいです。

とはいえ、【対策】を一人でやり切るのは正直難しいです。。。
【難しい要素1】、【難しい要素2】、【難しい要素3】。
これを一人でやろうとすると、どうしても主観が入ってしまう。

僕の経験上、【良い結果】が出る人ほど、【第三者】を壁打ち相手にしています。
【CTA】
```

## 相性の良いテーマ
- 項目が6〜8個に確定するテーマ（面接の質問、書類の欄、確認事項、評価の観点）
- 各項目に「相手が見ていること」と「正解の答え方」の2軸が立てられるテーマ
- 読者が「対策範囲が分からない」ことで不安になっているテーマ
- 一覧で再掲したときに1行でまとまるテーマ

## 相性の悪いテーマ
- 項目が3〜4個しかないテーマ（網羅感が出ない。結論先出し型のほうが向く）
- 項目が10個を超えるテーマ（各項目を4段で書くと読み切れない。網羅リスト型にする）
- 「相手」が存在しないテーマ（この型は常に相手の目線で書くので、相手がいないと成立しない）
- 正解が人によって変わるテーマ（「受かる人の答え方」が言い切れない）

## 文体・見た目のメモ
- 文章量：2,000〜3,500字（記事構文。140字ルールは適用しない）
- 1項目は250〜350字。全項目で同じ4段を崩さない（崩すと一覧性が落ちる）
- 見出しは記号なしの短文で置く（「面接官が自己紹介で確認していること」「受かる人の答え方」）
- 重要度マークは ★ を1〜2箇所だけ。付けすぎると効かない
- NG例は ・ か ● で2〜3行。並べすぎると説教に見える
- 一覧の再掲は「①　項目　→　要点」。矢印の前後は全角スペース
- 「・・・」「。。。」を各1箇所だけ使う（余韻と本音のトーンが出る）
- 絵文字なし

## ⚠️ 運用上の注意
- 各項目の「相手が確認していること」は、**発信者の立場で実際に見ているもの**として書く。
  一般論の寄せ集めにすると、この型の価値（裏側の開示）が消える。
- 「〇%改善した」のような**数字は読者が入れる側**。セリフ例は〇〇のプレースホルダで書く。
  出典のない統計を本文に置かない。
- 末尾のCTAで**外部サービス名を出すのは、アカウントカードに登録がある場合だけ**。
  登録がなければ、そのアカウントの登録済みCTA定型文に差し替える。
