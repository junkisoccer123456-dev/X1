# 構文名：n日間ロードマップ型

## この構文が読まれやすい理由
- 冒頭が統計ではなく**現場での観察**。「〜と聞くと、ほぼ全員が〜と答えます」は、聞いている側にしか書けない。
- 問題提起が「できているつもりと実態のズレ」。読者が自分に当てはめやすく、しかも責められていない。
- 「印象です」と断定を避けているので、反論が出にくい。数字を出していないのに説得力がある。
- 解決策を**自作のロードマップ**として出す。情報のまとめではなく、作ったものとして提示される。
- 「1日15〜30分でOK」で着手のハードルを下げる。ここがないと保存されて終わる。
- 「〇〇順に並べてます」で並び順に意味を与える。通読する理由になる。
- 本文に中身を一切書かず「1日目」＋↓ で切る。リプを開くしかない状態を作る。
- 各日の締めが「やること」ではなく**到達状態**。読者がその日の合格ラインを測れる。

## 基本構造
```
①権威フック（立場）＋現場での観察（〜と聞くと、ほぼ全員が〜と答えます）
 ↓
②問題提起（ただ〇〇の話に入ると、そこで止まる方が多い印象です）
 ↓
③「そこで【〇〇n日間ロードマップ】を作りました」
 ↓
④着手のハードルを下げる一言（1日15〜30分でOK）
 ＋並び順の根拠（面接で差がつく順に並べてます）
 ↓
⑤「1日目」＋↓ で切る（中身は出さない）
 ↓
⑥【リプ n日目】見出し
　　　　　　　位置づけ1行
　　　　　　　・3項目
　　　　　　　今日のゴール1行（到達状態で書く）
 ↓
⑦最終日は総復習。1〜n-1日目の要点を箇条書きで再掲し、到達水準を宣言して終わる
```

## 抽象テンプレート
```
【立場】してますが、【対象読者】に「【よくある質問】」と聞くと、ほぼ全員が【できると答える】と答えます。
ただ【一段深い論点】の話に入ると、そこで止まる方がかなり多い印象です。

そこで【〇〇n日間ロードマップ】を作りました。

1日【所要時間】でOK。
【並び順の根拠】順に並べてます。

1日目

↓

（リプ）
n日目 【その日のテーマ】

【なぜこの日が必要か／位置づけ1行】

・【項目1】
・【項目2】
・【項目3】

【今日の合格ライン1行】
```

## 相性の良いテーマ
- 「できているつもり」が起きやすい領域（触ったことはあるが説明はできない）
- 順番に意味がある学習内容
- 1日3項目 × 10日に割れる範囲

## 相性の悪いテーマ
- 順番が関係ないテーマ（並び順の根拠が作れない）
- 1日3項目に収まらない大きすぎる領域（別の型に分けたほうがよい）
- 手を動かさずに終わるテーマ（宿題が出せないと続かない）

## 運用上のメモ
- 5日目あたりに「ここが一番差がつく」と山場を置くと、中だるみしない。
- 途中に「今日の宿題」として手を動かす指示を1〜2回混ぜる。
- 評価する側の視点を混ぜると強い（「〜を見ています」）。
- 各日の締めを「やること」で書かない。**到達状態**で書く。
