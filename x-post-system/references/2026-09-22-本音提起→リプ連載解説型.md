# 参考投稿（原文）

```
ITエンジニアの面接で、実は地味に多い見送り理由が「技術は優秀そうなのに、この人とは一緒に働きたくない」と思われるパターン。

今は情報も多いので、技術力をどう上げるかには熱心な人が多いです。ただその一方で、"チームでどう振る舞うか"がスッポリ抜けてる人が一定数いるな、と面接してて感じます。
企業が30代以降のエンジニアに期待してるのは、一人で書ける力以上に「この人と組めば現場が回りそう」という安心感だったりします。
※媚びろとか、愛想よくしろという話ではないです。

もちろん、どう頑張っても合わない人や現場もあるので、そこは入る前の見極めが大事かと。ただ普段の振る舞いを少し意識できる人は、面接でもマジで信頼されやすいです。
ここを30代のうちに整えておくと、その後のキャリアがかなり楽になります。
「一緒に働きたくない」と思われがちな言動、下に7個...

【リプ①】レビュー指摘に「いや、でも」から入る人
実際、模擬でコードを見せて「ここ可読性どうですか?」と聞いたら、最後まで聞かず「いや、これが一番速いんで」と返した方がいました。
速さ自体は正しいんです。ただ採用側が見てるのは正誤じゃなく「指摘を一回受け止められるか」。入社後、若手やレビュアーと同じ衝突をする画が浮かぶんですよね。
正しくても、まず「たしかに」と一拍置ける人が一気に評価上がります。

【リプ②】前職のコードや人をdisる人
【リプ③】要件を聞く前に実装方針を語り出す人
【リプ④】「自分はこう書きたい」一辺倒の人
【リプ⑤】質問にマウントで返す人
【リプ⑥】失敗を全部"他責"で語る人
【リプ⑦】詰められた瞬間に黙る/不機嫌になる人
（各リプは「見出し → 実際にあった場面 → 採用側の解釈 → どうすれば評価されるか」の4段構成）
```

## 気づいたこと（メモ）
- 冒頭が「技術は優秀そうなのに」という逆説。優秀な人ほど自分ごと化する
- 予防線（※媚びろという話ではない／合わない現場もある）を入れて反発を先に潰している
- 本編は"考え方"、リプに"具体例"を置く分業。本編だけでも成立する
- 各リプが「見出し→実際の場面→採用側の解釈→改善策」の4段で統一されている
- 場面描写にセリフが入っている（「いや、これが一番速いんで」）ので画が浮かぶ
- 「下に7個...」で本文を終わらせ、リプへ確実に誘導している
