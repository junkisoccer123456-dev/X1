# 参考投稿（原文）

```
先日、面接にきた方の転職活動の状況がこんな感じで、
現役エンジニアの方の指標になりそうだったので、ぼくの肌感を添えて共有しますね。

・年齢：29歳
・経験：Webバックエンド3年（自社開発）
・技術スタック：Java／Spring Boot、AWS（EC2・RDS中心）、設計〜コードレビューまで一通り
・直近年収：480万
・希望年収：600万〜
・応募先：自社開発・SaaS系（バックエンド）

活動結果がこちら。
・最終内定：3社
・期間：約1ヶ月半

面接にきたときの肌感を正直に言うと、「話していて筋が通っている人」でした。
僕が面接で本当に見ているのは、年数や使える言語より「設計でどんな判断をしてきたか」なんですよね。（中略）
内定3社が出たのも、たぶん「3年やってます」だけでは決まっていません。
年収交渉は、内定を複数並べた瞬間に一気に有利になります。
精度高く母数を作って、面接で自分の判断を語れる。これが経験者の転職でいちばん強い戦い方かと。
```

## 気づいたこと（メモ）
- 「指標になりそうだったので共有しますね」＝善意の共有という入り方。宣伝感ゼロ
- スペックを箇条書きで出すことで、読者が自分と比較できる（自分ごと化装置）
- 結果（内定数・期間）を先に出してから、理由の解説に入る
- 解説部分が「僕が面接で本当に見ているのは〜」と、発信者にしか言えない情報になっている
- 最後に再現可能な戦い方へ一般化して締めている

## ⚠️ 運用上の注意
この構文は**実在の候補者の事例**が前提。数値を創作すると嘘になるため、
生成時はスペック部分を【　】のプレースホルダにし、実際に面接した方の数字を入れて使う。
