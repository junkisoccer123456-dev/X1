# 参考投稿（原文）

```
エンジニアが覚えると「点と点がつながる」知識5選

個別に勉強してたけど、後から全部つながった。

HTTP
↓
API
↓
認証・認可
↓
DB
↓
クラウド

最初は全部別の技術に見える。
でもシステム構成図を見ながら勉強すると、急に理解できるようになった。
技術は単体より「つながり」で覚えるのがおすすめ。
```

## 気づいたこと（メモ）
- 1行目がタイトル形式（「〇〇5選」）。中身を見る前に価値が分かる
- 2行目の「個別に勉強してたけど、後から全部つながった」が共感フック
- ↓ で縦に並べるだけで「順番・因果」が視覚的に伝わる。読む負荷ゼロ
- 「最初は〜。でも〜」の転換で、読者の現在地（分かってない状態）を肯定してから引き上げている
- 締めが方法論の一言。押しつけがなく保存されやすい
