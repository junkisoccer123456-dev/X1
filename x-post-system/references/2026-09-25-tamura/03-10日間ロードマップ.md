# 参考投稿①｜SQL 10日間ロードマップ（リプ10連投）

## 原文（元ポスト）

```
IT企業でエンジニア採用してますが、微経験の方に「SQLは書けますか」と聞くと、ほぼ全員が書けますと答えます。ただJOINとインデックスの話に入ると、そこで止まる方がかなり多い印象です。

そこで【SQL10日間ロードマップ】を作りました。

1日15〜30分でOK。
面接で差がつく順に並べてます。

1日目

↓
```

## 原文（リプ1〜10）

各リプは「n日目 見出し」＋「位置づけ1行」＋「・3項目」＋「今日のゴール1行」で統一。
最終日だけ構造が変わり、1〜9日目の要点を箇条書きで再掲する総復習になっている。

```
「張れば速くなる」ではなく、トレードオフとして説明できるかを見ています。
```

```
リプ10日目 総復習
```

# 分析メモ

## 1. 冒頭フック・権威性
- 「IT企業でエンジニア採用してますが、」の立場提示から入る。ここは固定。
- そのあとに**現場での観察**を置く。「〜と聞くと、ほぼ全員が〜と答えます」。
  統計ではなく、聞いている側だから言える一次情報になっている。

## 2. 問題提起
- 「ただ〇〇の話に入ると、そこで止まる方がかなり多い印象です」
- できているつもりと実態のズレを突く形。読者が自分に当てはめやすい。
- 「印象です」と断定を避けているのが上手い。数字を出していないので反論されにくい。

## 3. 興味維持の仕掛け
- 「そこで【〇〇n日間ロードマップ】を作りました」＝問題に対する解決策を自作物として提示。
- 「1日15〜30分でOK」＝**着手のハードルを下げる**。ここがないと保存だけされて終わる。
- 「面接で差がつく順に並べてます」＝**並び順に意味がある**と宣言する。通読の理由になる。
- 本文に中身を一切書かず「1日目」＋↓ で切る。リストを見せないので、リプを開くしかない。

## 4. リプの構造
- 「n日目 見出し」→「位置づけ1行」→「・3項目」→「今日のゴール1行」。
- 3項目は覚えられる量に抑えている。網羅ではなく厳選。
- 最後の1行が**その日の合格ライン**になっている（「NULLの扱いを説明できれば今日はOK」）。
  やることではなく、到達状態で締めているのがこの型の肝。
- 5日目に「面接で最も差がつく領域です」と山場を置き、中だるみを防いでいる。
- 6日目の「今日の宿題」など、手を動かす指示が混ざっている日がある。

## 5. 最終日の扱い
- 10日目だけ構造が変わり、1〜9日目の要点を箇条書きで再掲する。
- 締めは「ここまで説明できれば、微経験としては十分な水準」＝到達水準の宣言。
  読者が自分の現在地を測れる形で終わる。

## 6. 文体・見た目
- 本文は約180字。各リプは120〜180字。
- 絵文字なし。記号は ・ と ↓ のみ。
- 評価する側の視点が混ざる（「〜を見ています」）。ここが採用担当アカウントならではの強み。
